# Архитектура Minty Launcher

## Компоненты

- `app.rs`: окно `egui`, страницы, Skin Studio, журнал, настройки и фоновые задачи.
- `config.rs`: настройки пользователя, выбранный каталог игры и локальный журнал.
- `skin.rs`: импорт, проверка размеров и экспорт PNG-текстур Minecraft 64×64 / 64×32.
- `auth.rs`: Microsoft Device Code Flow, Xbox Live/XSTS, Minecraft Services и проверка лицензии. Refresh token сохраняется в системном credential store.
- `minecraft.rs`: получение манифеста, client JAR, библиотек, natives и assets, проверка опубликованных SHA-1 и подготовка аргументов JVM.
- `runtime.rs`: поиск Java и загрузка Temurin JRE подходящей версии.

`build.rs` компилирует `java/MintyBootstrap.java` в Java 8 bytecode. Bootstrap выполняет финальный запуск JVM Minecraft и передаёт код завершения.

## Пользовательские данные

- `settings.json` — настройки лаунчера в пользовательском config directory.
- `launcher.log` — журнал лаунчера в data directory, без записи access/refresh token.
- `runtimes/` и `bootstrap/` — загруженные Java Runtime и bootstrap-класс.
- Выбранный каталог Minecraft — версии, библиотеки, assets, natives и `options.txt`.
- `options.txt.minty-backup` — резервная копия исходных игровых настроек для профиля «Слабый ПК».

## Производительность

Профиль «Слабый ПК» уменьшает дальность прорисовки, simulation distance, частицы, облака и некоторые визуальные эффекты. Он ограничивает выделение Java-памяти 2 GB и использует консервативные параметры G1GC. До изменения `options.txt` Minty сохраняет копию и восстанавливает её после отключения профиля.

## Границы безопасности

1. Сетевые загрузки выполняются через TLS.
2. SHA-1 применяется для сравнения с хешами, опубликованными Mojang; это проверка целостности загрузки, а не античит.
3. ZIP-архивы извлекаются с проверкой безопасного относительного пути.
4. Microsoft refresh token не хранится в `settings.json`.
5. Офлайн-сохранённый PNG-скин не становится сетевым профилем и не отображается автоматически в чистом Vanilla-клиенте.
